# PRD --- Sayyed Kashaf Personal Data Science Portfolio

## 1. Product Overview

**Product:** Personal Portfolio Website\
**Owner:** Sayyed Kashaf\
**Role:** B.Sc. Data Science Student\
**Timeline:** 2025--2028\
**Primary Goal:** Present Kashaf's education, projects, skills,
experience, and current learning focus in a clean, professional
portfolio that can be shared with recruiters, internship coordinators,
and collaborators.

## 2. Portfolio Positioning

The website should communicate:

> A Data Science student building practical projects across data
> analysis, AI, backend development, and cybersecurity.

The portfolio should feel personal and student-focused rather than
pretending to be an experienced ML engineer.

## 3. Target Audience

-   Data science / data analyst recruiters
-   Internship recruiters
-   Early-career hiring managers
-   College faculty and peers
-   Potential project collaborators

## 4. Primary Goals

1.  Clearly introduce Kashaf within the first few seconds.
2.  Show practical projects with links to source code.
3.  Present education and experience chronologically.
4.  Make GitHub and LinkedIn easy to access.
5.  Show current learning/focus areas.
6.  Provide a simple way to contact Kashaf.
7.  Work well on desktop and mobile.

## 6. Design Requirements

### Visual Direction

-   Modern
-   Minimal
-   Professional
-   Student/developer focused
-   Clean typography
-   Strong whitespace
-   Subtle animations
-   No excessive gradients
-   No unnecessary stock imagery

A restrained teal accent can be used to create a recognizable personal
identity.

### Responsive Design

The website must work on: - Desktop - Tablet - Mobile

### Accessibility

-   Good color contrast
-   Keyboard-friendly navigation
-   Descriptive link text
-   Alt text for meaningful images
-   Visible focus states
-   Semantic HTML

## 7. Functional Requirements

-   Sticky or accessible navigation
-   Smooth section navigation
-   Project cards
-   GitHub project links
-   LinkedIn link
-   Responsive mobile menu
-   Timeline component
-   Skills section
-   Contact section
-   Optional downloadable resume
-   SEO title and description
-   Favicon
-   Open Graph metadata

## 8. Non-Functional Requirements

-   Fast initial load
-   Mobile responsive
-   Easy to maintain
-   Projects should be data-driven where practical
-   No hard-coded repeated project-card markup if avoidable
-   Clean component structure
-   Deployable to a modern static hosting platform

## 9. Success Criteria

The portfolio is successful when a recruiter can answer these questions
quickly:

1.  Who is Kashaf?
2.  What is she studying?
3.  What can she currently work with?
4.  What has she built?
5.  Where can the projects be verified?
6.  How can she be contacted?
